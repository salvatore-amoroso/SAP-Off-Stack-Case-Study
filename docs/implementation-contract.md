# Poller behavior contract version 1

This is the normative functional specification for the ABAP, Node.js and Rust HTTP pollers. All three consume the same read-only OrderPositions OData V4 collection. Version 1 implements the flat full-scan profile; SAP also exposes order headers and their positions for navigation. The CDS and native HANA paths reuse the same row validation, canonicalization and hashing after path-specific value conversion. Their query/transport behavior is defined by the [nine-path protocol](nine-benchmark-protocol.md). Nested expansion is outside these comparisons.

## Input and execution

Required settings: service_root (absolute HTTP(S) URL ending in /), SAP client (default 001), expected_rows (nonnegative integer), expected_digest (64 lowercase hex digits). Credentials are supplied through environment/runtime destination configuration, never repository files. Optional settings: scans=1, interval_ms=1000 (positive integer), request_timeout_seconds=10, scan_timeout_seconds=120, page_size=500, max_body_bytes=8388608, max_pages=10000. Integer bounds: expected_rows 0..2147483647; scans 1..1000000; interval_ms 1..3600000; request_timeout_seconds 1..3600; scan_timeout_seconds 1..86400; page_size 1..10000; max_body_bytes 1..67108864; max_pages 1..1000000. Reject fractional values and overflow before requesting anything. Initially one request and one scan in flight, no retries, no redirects, no cookie persistence. Plain HTTP is permitted for this explicitly local lab; HTTPS must verify certificates unless the operator explicitly selects the documented local-trial certificate exception. Never apply a TLS exception globally.

First request path OrderPositions; query, in this order: $select=OrderId,PositionNumber,CustomerId,OrderDate,MaterialId,Quantity,Unit,NetAmount,Currency and $orderby=OrderId,PositionNumber; include sap-client=001 (or configured client). Use normal URL encoding. Headers: Accept: application/json;odata.metadata=minimal;IEEE754Compatible=true; Prefer: odata.maxpagesize={page_size}; Accept-Encoding: identity. Reuse HTTP connections. $top is not added to full scans.

Successful page: HTTP 200, valid UTF-8 JSON object, value is an array. A present nonstring @odata.nextLink is SCHEMA before rows are processed; an empty string is NEXTLINK after page rows are processed. Ignore annotations and unknown properties. Reject null/missing/wrong-typed selected row values. The supported SAP JSON domain contains Unicode scalar values. Enforce at most 128 nested JSON objects/arrays, counting the root object as level 1 and including unknown properties; deeper input is SCHEMA before any rows are processed. Brackets inside quoted strings do not count toward nesting. Duplicate property names and unpaired surrogate escapes are outside this OData response contract; do not claim equivalence for arbitrary parser extensions.

## Rows and canonical bytes

Selected fields, all JSON strings, in this exact canonical order:

OrderId, PositionNumber, CustomerId, OrderDate, MaterialId, Quantity, Unit, NetAmount, Currency.

Identifiers are ASCII: OrderId [A-Za-z0-9_-]{1,20}; PositionNumber exactly six digits; CustomerId [A-Za-z0-9_-]{1,10}; MaterialId [A-Za-z0-9_-]{1,18}; Unit [A-Z]{1,3}; Currency [A-Z]{3}. Preserve spelling and leading zeros. OrderDate is a real Gregorian date YYYY-MM-DD, years 0001..9999. Quantity and NetAmount are unsigned ordinary decimal strings: digits with an optional dot followed by digits, no whitespace, signs or exponents. Normalize leading integer zeros to one zero; pad Quantity to three fractional digits and NetAmount to two. Reject excess scale (even zero trailing digits beyond the scale), Quantity with over ten significant integer digits, NetAmount with over thirteen significant integer digits. Never use floating point. Zero is valid.

Require composite keys (OrderId, PositionNumber) to be strictly ascending in received order across all pages; compare ASCII strings lexicographically. Do not sort locally. Empty pages are allowed, including an empty page with a continuation.

Initialize incremental SHA-256 with UTF-8 bytes of `sap-polling-lab` + TAB + `1` + LF. For every row, append normalized field values joined by one TAB and followed by one LF. No column-name header, BOM, CR, padding spaces, or final extra blank line. Final digest is lowercase hexadecimal. Digest and ordering state continue across page boundaries. Memory must remain bounded by a page, not a full scan.

## Continuation and limits

Service roots and continuation references use printable ASCII URI syntax (bytes 0x21 through 0x7e); encode spaces and Unicode as percent-encoded UTF-8. Reject raw whitespace and non-ASCII characters. Resolve @odata.nextLink against the current response URL using standard URI resolution (absolute, relative path, root path and query-only links). Before sending credentials require the same canonical origin and a path inside the configured service root. Reject userinfo, fragments, protocol-relative references, literal backslashes, control characters, encoded slash/backslash, and path segments that decode to dot or dot-dot. An encoded dot within an ordinary name such as Order%2ePositions is allowed. Reject changes to an explicit sap-client parameter. Continuation query parameters and opaque tokens are preserved. Detect URL cycles; bound the visited set by max_pages. HTTP redirects are HTTP_STATUS failures and must not be followed.

Count every attempted page; max_pages prevents starting a request beyond the limit. A cap failure reports the next page_index, the number of already attempted pages, and null http_status. A URL cycle detected while validating a continuation reports the current page and its status. max_body_bytes is a completed-response acceptance limit: a completely received oversized body is LIMIT; an interrupted or timed-out transfer is TRANSPORT/TIMEOUT first, even if Content-Length already exceeded the limit. Node.js/Rust discard excess buffered data while continuing to receive under the deadline. ABAP's classic HTTP API buffers the native response before application code can check its size; therefore the limit is not a native ABAP receive-memory cap. A request deadline includes full body receipt. A scan deadline includes parsing and checksums; check it before/after requests and processing and limit each request by remaining scan time. ABAP uses whole-second transport timeouts; do not claim sub-second cancellation parity. Finish only when no nextLink remains; then compare row count before comparing digest. Failed scans never contribute validated rows.

## Results and errors

One JSON object per scan on stdout (ABAP exports the same structure). Required functional fields: schema_version=1, scan_index (zero based), outcome ('ok'/'error'), rows (observed and validated rows processed before failure), pages (attempted pages), digest (completed digest on successful scan, null on error), error (null on success or object with code, page_index (one based, 0 before first request), http_status (completed-response status when applicable, otherwise null; always null for TIMEOUT and TRANSPORT)). Metrics are a separate object: elapsed_ms, body_bytes, missed_slots. All three normalize outcomes/errors to this schema. Property order is not significant. Metric values are expected to differ. stdout contains no other text; diagnostic stderr contains no secrets.

Error precedence: invalid config CONFIG; transport failure TRANSPORT; exceeded deadlines TIMEOUT; non-200 status HTTP_STATUS; body/page/cycle bounds LIMIT; invalid JSON/UTF-8/field/envelope SCHEMA; nonascending row ORDER; unsafe next link NEXTLINK; final row count COUNT; final digest DIGEST. Complete body receipt is required even for non-200 responses, under the same deadline; discard their content and inspect status before body limits or response schema. For a valid page process rows before validating its continuation. A failed row is not added to rows/digest. Body limits take precedence over schema. Do not emit a completed digest on error.

Run scan 0 immediately. Slots are measured from a monotonic run origin. After each scan choose the first future interval slot; elapsed slots are missed and never queued. For scans=1 do not wait after the result. CONFIG, SCHEMA, ORDER, NEXTLINK, LIMIT, COUNT, DIGEST and HTTP 400/401/403/404 terminate a multi-scan run. Other transport/timeouts/HTTP failures permit the next scheduled scan. CLI exit is 0 only if every scan succeeds; otherwise 1 (CONFIG uses 2). Tests may use injected page responses; live tests use the same SAP data and permissions.

## Conformance

contracts/fixtures.json contains shared row/page fixtures and expected outcomes, counts and digests. Each implementation must expose an offline fixture runner using the same normalization, page processing, ordering and digest core as its HTTP poller. Shared live fault-server tests cover HTTP statuses, next links, redirects, limits and timeouts. Run the exact fixtures in ABAP Unit or a class-run test adapter, not an independently rewritten validator. Finally compare all three against the frozen seeded SAP dataset. A passing Node/Rust test suite alone is not proof of ABAP parity.

The seed uses 1000 headers and 5 positions each. OrderId is the 20-digit zero-padded order number; PositionNumber is 000010, 000020, 000030, 000040 or 000050; CustomerId is C plus the nine-digit order number; OrderDate is 2026-01-01; MaterialId is M plus the seventeen-digit position index (1..5); Quantity is the position index with three zero fractional digits; Unit is EA (verify service wire representation); NetAmount is order number plus position index, with two zero fractional digits; Currency is CHF. Header total is the sum of its five positions. Timestamp values are excluded from the selected payload and digest. If SAP translates the unit code on the wire, resolve that through a single contract/seed change and rerun every implementation; never patch one client independently.
